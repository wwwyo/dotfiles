`solo-product` skill の保守規約。

- `SKILL.md` はルーターに徹し、判断・手順の正本は `references/` に置く。
- reference は 1 reference = 1 やること。金額・制限・プラン別機能など変わりやすい主張には一次資料 URL と確認日を付ける。未確認のことは未確認と書き、推測で上限・保証を書かない。
- 公開・停止・課金の主張を書くときは「通知」と「強制停止」を混同しない。根拠のない hard cap・認証保証を書かない。
- 新しい学び（abuse 事例・設定ミス・障害）を追記するときは既存 reference と dedup し、検証可能な形（コマンド・設定キー・失敗条件）で書く。session-consolidate がこの skill を育てる。
