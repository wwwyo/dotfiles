# Story Format

story はプロダクトに1つ。repo root `AGENTS.md` の `## Story` 節に置く。機能ごとには書かない（機能ごとに書くと user story の backlog に戻り、却下の基準として使えなくなる）。

## 構造

雛形は [templates/story.md](../templates/story.md)。

```md
## Story

{一文: 誰の生活で、何をするか}

Core actions:
- {ユーザーが実際にやること} — {cycle: 日次 / 週次 / 月次 / 年数回}
- {…}
```

## 一文

- **人が主語**。「〜な knowledge layer」のようにモノを主語にしない
- **機能名を書かない**。機能を書いた瞬間に「何を作るか」が固定され、却下の基準にならない
- **口で言える長さ**。部屋にいなくても他人の口を経由して歪まずに伝わることが条件
- 例: 「気にかけている人や組織について、いま何が起きているかが分かる」（Twitter）

## Core actions

- ユーザーが**実際にやること**。「開いた」「ログインした」「サインアップした」は不可
- 複数あってよい。全部書く
- 各行に **cycle**（期待頻度）を付ける。頻度は高い必要が無い（LinkedIn の「声をかけられたら返事をする」は年1〜2回で成立する）

## 判定

書いた story が機能しているかは次の2つで判定する。両方通らなければ書き直す。

1. **他人が自分の言葉で言い直せるか** — 言い直せなければ伝播しない
2. **それで機能を1つ却下できるか** — 却下できなければ基準になっていない。何でも収まる一文は story ではない

一文で言おうとして「A で、かつ B で」と接続詞が要るなら、まだ story になっていないか、2つのプロダクトを1つの器に入れている。

## 変えるとき

story は最も変わりにくい artifact。機能は story の周りで動き、story は機能に合わせて曲げない。変えるのは pivot で、一方通行の決定として ADR に残す。
