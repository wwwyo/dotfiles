# skill の plugin 配布（Claude・Codex・pi・Devin）

共有 skill の正本は `wwwyo/skills` repo の `.agents/skills/`（canonical checkout は `~/src/github.com/wwwyo/skills`）。各 tool へは plugin / package として配り、`~/.agents/skills`・`~/.claude/skills` への symlink では配らない。repo 側の layout と manifest の生成は wwwyo/skills の `AGENTS.md` が正本。ここには tool ごとの読み込み方の差を置く（2026-11-10 に Claude Code 2.1.316・codex-cli 0.166.0・pi 1.4.0 で確認）。

| tool | 登録 | 読む場所 | 編集の反映 |
| --- | --- | --- | --- |
| Claude Code | core・design は claude.ai のアカウントに入れたもの（`core@synced`・`design@synced`）。local は `extraKnownMarketplaces` の directory source から `local@wwwyo`。`enabledPlugins` で `*@synced` を有効、`core@wwwyo`・`design@wwwyo` を無効にする | core・design は `~/.claude/plugins/synced/<bucket>/<plugin>/` の copy。local は元フォルダを直接読む（`claude plugin list --json` の `readFromFolder`） | core・design は main への merge → claude.ai の同期 → Claude Code 側の同期（session 開始時）を経て届く。local は次の session 開始か `/reload-plugins` |
| Codex | `[marketplaces.wwwyo]`（local source）と `[plugins."core@wwwyo"]` 等 | `~/.codex/plugins/cache/wwwyo/<plugin>/<version>/` の copy | `codex plugin add <plugin>@wwwyo` を再実行するまで反映されない（同じ version でも上書きされる）。CLI の起動（`codex debug prompt-input`）では cache は更新されなかった。desktop app の再起動で更新されるかは未確認 |
| pi | `settings.json` の `packages` にローカルパス | その場で読む（copy しない）。未 commit の編集も見える | `/reload` か次の起動 |
| Devin | plugin を使わず `~/.config/devin/skills` を `.agents/skills` へ dir link | link 先を直接読む | 次の起動 |

- **Codex の cache copy は symlink を落とす**。plugin root の外を指すものも中を指すものも消えるため、skill を symlink で plugin root に集める layout は Codex では空になる。plugin root は実ファイルを含む dir にし、`.codex-plugin/plugin.json` の `skills` に配列で skill dir を 1 つずつ列挙する（`skills` は文字列だけでなく配列も受け付け、dir 単位の指定も効く）。plugin ごとに root を分ける必要があり、core = repo root、design = `.agents/skills`、local = `.agents` にしている。root にできる dir はこれで尽きるので、plugin は増やさない
- **Codex の core root は repo root なので `.git` も cache に copy される**。容量の問題が出たら plugin root の切り方を見直す
- **Codex で読まれた skill の確認**は `codex debug prompt-input hi` の出力を `core:<name>` で grep する（API に届かなくても prompt は出力される）。Claude は `claude plugin details core@synced`（local は `local@wwwyo`）、pi は `pi --mode rpc --offline --no-session` に `{"type":"get_commands"}` を送ると `skill:<name>` と読み込み元 path が返る
- **plugin 経由の MCP は core の `mcphub`・`mcp-media` と local の `blender`・`openscreen` の 4 つ**。`openscreen` は OpenScreen アプリが 127.0.0.1:47821 に出す MCP（http、bearer）で、token は local plugin の `userConfig`（`openscreen_token`、sensitive なので Keychain に入る）から header に入れる。token は OpenScreen の Settings → MCP Server で表示・再発行でき、起動ごとには変わらない。コピーして `pbpaste | jq -R '{openscreen_token: .}' | claude plugin configure local@wwwyo --values-stdin` で入れる（再発行したら入れ直す）。アプリを起動していないと接続失敗になる。`mcphub` は MCP portal `https://mcp.wwwyo.dev/mcp`（http、OAuth は Claude Code の `/mcp` でログインし、credential は repo に書かない）で、Claude Code では tool が `mcp__plugin_core_mcphub__*` になる。`mcp-media` は Code Mode off の portal `https://mcp-media.wwwyo.dev/mcp`（いまは camera だけ）で、書き方と OAuth は `mcphub` と同じ。tool は `mcp__plugin_core_mcp-media__*` になる。dotfiles の Claude 設定の allow は `mcp__plugin_core_mcphub__*` だけなので、撮影は毎回確認が出る。Codex の core plugin には載せておらず、Codex・pi・Devin は dotfiles の各 client 設定に `mcphub` を持つ（[mcp-portal](mcp-portal.md)）。`blender`（mcp-for-blender）は手元の Blender を操作する stdio の MCP で、portal に集約しない例外。Claude Code の local plugin にだけ載り、Codex・pi・Devin には配っていない。`uvx mcp-for-blender==<version>` で exact pin し、更新は 7 日 cooldown に従う。`DISABLE_TELEMETRY=true` で匿名の利用記録も切る。`uvx` は mise global の uv なので、Claude Code は mise の PATH が通った環境から起動する。Blender 側の addon（`uvx mcp-for-blender install-addon`）と、Blender での Start MCP Server は手元での操作
- **plugin skill は名前空間付きになる**（Claude・Codex は `core:pr`）。pi は名前空間を付けない
- **tool が配る skill は plugin に入れない**。Orca の `orca-cli`・`orchestration`・`orca-computer-use` は dotfiles の `.agents/skills/` で追跡し、Orca が `~/.agents/skills` 経由で更新する（[orca](orca.md)）。Codex・pi は `~/.agents/skills` を直接読み、Claude は dotfiles の `.claude/skills` の symlink で読む。plugin にも入れると Claude・Codex で `local:orca-cli` と `orca-cli` が並び、repo 側の copy は Orca の更新に追従しない。Devin の `~/.config/devin/skills` はこの repo だけを指すため、Orca の skill は届かない
- **core・design はアカウントの plugin を正本にし、local だけ手元の marketplace から入れる**。claude.ai の Customize > Plugins で marketplace `wwwyo/skills` を追加し core・design を有効にすると、cloud の Projects スレッドにも手元の Claude Code にも `core@synced`・`design@synced` として届く（cloud の Projects スレッドは `~/.agents` も repo の `.claude/skills` も読まず、アカウントの plugin だけが届く）。local はアカウントに入れると cloud にも届くため、手元の directory marketplace から `local@wwwyo` で入れる。手元では `core@wwwyo`・`design@wwwyo` を無効にして重複させない。merge 前の core を Claude で試すときは `claude --settings '{"enabledPlugins":{"core@wwwyo":true,"core@synced":false}}'` でその session だけ checkout に切り替える（`--plugin-dir` は marketplace の root を plugin として読まない）
- skill から自分の tools を呼ぶときは `~/.agents/skills/...` の絶対 path を書かない。cloud・Codex cache では存在しない。agent が読む手順は SKILL.md の dir からの相対 path で書き、scheduled task・hook など agent 以外の呼び出し元は canonical checkout（`~/src/github.com/wwwyo/skills/.agents/skills/...`）を指す
