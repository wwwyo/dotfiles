# ingest-to-markdown

ドキュメント(PDF/スライド/docx/…)を保存するとき、生バイナリのまま置かず [anydoc](https://github.com/firecrawl/anydoc) で Markdown に変換してから保存するための汎用スキル。

保存先・命名・後段の使い道は 呼び出し側の文脈で決める。このスキルは「入力を md に倒す」という一点だけを担い、どのリポジトリ・どのディレクトリでも成り立つ。

## なぜ md 化するのか

保存する一次情報は「後から grep で引ける / git diff で変化が見える / LLM が全文を読める」状態であってこそ stock として機能する。PDF や pptx をバイナリのまま置くと、読み込みが重く(画像として大量トークンを消費)、検索も差分も効かない。だから 保存の時点で md へ倒す。元ファイルは変換後に削除する(残すなら `--keep-source`)。

## 前提ツール

- `anydoc`。mise(npm backend)で入れる。PATH に無ければ script は失敗する。Rust 実装で決定的パーサのみを使うため、変換はローカル完結・API key 不要・1秒未満で終わる。
- `yt-dlp`(YouTube 取り込み専用。mise global で install 済み: `asdf:duhow/asdf-yt-dlp` plugin。PATH にある前提でよく、事前 install 作業は不要)。
- `anarlog`(字幕なし動画・ローカル動画の文字起こし専用)。brew では入らず、Anarlog.app の初回起動で `~/.local/bin/anarlog` に auto install される(後述の手順と MIGRATION.md の手動対応リスト参照)。
- 実行権限: anydoc 自体はネットワーク不要なので、sandbox 下でも動く。yt-dlp は youtube.com へのアクセスが要るので常に sandbox 解除。`anarlog` は既定の source(local)なら local DB を読むだけでネットワーク不要だが、`meetings --source auto|cloud ...`(`--source` は leaf より前に置く)は cloud に出る場合がある。

### 対応形式と、対応していないもの

対応: `doc` `docx` `docm` / `ppt` `pptx` `pptm` / `xls` `xlsx` `xlsm` `xlsb` / `odt` `ods` `odp` / `rtf` / `epub` / `csv` / `pdf`。

PDF はまず poppler でスキャン PDF(ページの大半が紙をスキャンした全面画像)かどうかを判定し、そこで経路が分かれる。

- 非スキャン PDF: anydoc で変換する。一部のページだけ文字層が無ければそのページを除いて残りを変換し、除外したページ番号を md 冒頭に記録する。全ページに文字層が無ければ変換せず失敗を返す。
- スキャン PDF: anydoc は使わず `pdftotext` でページごとの本文だけを抜く(ページを除いて poppler で作り直したスキャン PDF は anydoc が文字層を読めず、OCR 本文に見出し・表の推定をかける意味も薄いため)。空白を除いて20文字未満のページは文字層なしとして除外し、各ページの先頭に `<!-- page N -->`(元 PDF の 1 始まりのページ番号)を置く。全ページに文字層が無ければ変換せず失敗を返す。

スキャン判定は「ページ面積の50%以上を1枚の画像が覆うページが全体の80%以上」かつ「埋め込みフォントが無い(Acrobat の OCR 不可視レイヤー用フォント HiddenHorzOCR/HiddenVertOCR は除く)」の両方を満たすときだけ真になる。背景画像を敷いた電子的な PDF(スライド等)はフォントを埋め込むのでこれで弾ける。

いずれも poppler(pdfinfo/pdfimages/pdffonts/pdfseparate/pdfunite)が PATH に無いときはスキャン判定とページ除外を飛ばし、anydoc だけで動く(文字層が一部でも欠けていれば失敗を返す)。

非対応(旧 docling ではできていたもの):
- 画像ファイル(png/jpg 等) — anydoc は OCR をしない。
- Keynote `.key` — PDF か pptx に書き出してから取り込む。
- HTML — 対応形式に無い。web ページは Firecrawl 系の scrape skill か、素の fetch で取る。

## 手順

### 1. 保存先とファイル名を決める(呼び出し側の文脈で)

- 保存先ディレクトリは、そのプロジェクトの慣習に従う。一次情報を集める場所があればそこへ、無ければユーザーに合わせる。このスキルは特定パスを前提にしない。
- 保存先は `output_dir` 引数で直接指定する(コピーしてから変換する必要はない)。入力がプロジェクト外(例: `~/Downloads/foo.pdf`)でも、出力先だけプロジェクト内を指せば md はそこに出る。
- ファイル名は変換元の stem を引き継ぐ(例: `foo.pdf` → `foo.md`)。suffix 付き(例: `foo.local.pdf`)ならそれも維持される。
- 注意: 既定で変換元を削除するので、入力がプロジェクト外の原本(ダウンロードした資料など)で消したくないときは `--keep-source` を付ける。スキャン PDF でページを除外したときは、`--keep-source` の指定が無くても原本を残す(手順4で agent が原本を確認する運用のため)。

### 2. 同梱スクリプトで変換する

この skill ディレクトリの `scripts/ingest.sh` を使う(呼び出し時は絶対パスで指すのが安全):

```bash
<skill_dir>/scripts/ingest.sh <input> [output_dir] [options]
```

| option | 既定 | 説明 |
|--------|------|------|
| `output_dir` | input と同じ場所 | 出力先。保存先は呼び出し側が決める |
| `--keep-source` | 削除する | 変換後も元ファイルを残す(スキャン PDF でページを除外したときは指定が無くても残る) |
| `--format <fmt>` | 中身から自動判定 | 入力形式を明示。CSV など署名の無い形式で拡張子が当てにならないときだけ使う |
| `--` | — | 以降を位置引数扱い(dash 始まりパス対策) |

スクリプトは安全策込み: 入力と出力が同一ファイルに解決されるときは変換前に abort(成果物ごと消す事故を防ぐ)、変換失敗時は source を消さない、未知オプション/値欠落は usage で停止。

例(パスはあくまで例。実際は保存先の文脈で置き換える):

```bash
<skill_dir>/scripts/ingest.sh path/to/資料.pdf docs/refs/
<skill_dir>/scripts/ingest.sh ~/Downloads/deck.pptx raw/refs/ --keep-source
```

スクリプトを使わず直接叩く場合:

```bash
anydoc <input> --output <output.md>
```

### 3. 変換結果を確認し、掃除する

生成 md を開き、見出し・表・本文が壊れていないか確認する。anydoc は決定的パーサなので、docling のような OCR 由来の意味不明な記号列は出ない。代わりに 形式ごとに癖が違うので、そこを見る。

pptx / docx / xlsx はほぼそのまま使える。図形(AUTO_SHAPE)やグループ内の図形のテキストも拾い、bold・ネストリスト・リンク URL を保持する。実測ではスライド本文の取りこぼしはゼロだった。残るノイズは `/9\~12` のような不要なエスケープと `**` の付けすぎ程度で、実害は無い。

非スキャン PDF(anydoc 変換)は掃除が要る。テキスト層は正しく取れるが、レイアウト推定に以下の癖がある:

- 本文の誤 table 化: 段組やフッターを表と誤認し、本文が `||タイトルが入ります|` のような表に化けることがある。見つけたら普通の段落に戻す。これは行を消すだけでは直らない唯一のノイズなので優先して見る。
- 見出しレベルが意味と対応しない: フォントサイズ由来で `#`〜`#####` にばらけ、`# 表紙タイトル` の直後に `##### 小見出し` が来たりする。階層に意味を求めない。気になるなら手で均す。
- リンクの URL が落ちる: `[text](url)` にならず `<u>text</u>` になることがある。後から辿りたい URL がある資料は、変換後に元ファイルで確認して手で貼り直す。これを取りこぼすと後から復旧できない。
- フッター・ページ番号の混入: `© Company Inc.` やページ番号だけの行が本文に残る。機械的に消せる。

画像は痕跡ごと消える。anydoc は画像を md に一切残さない(docling の `<!-- image -->` に相当するものが無い)。つまり md だけ見ると「図があった」ことが分からない。図そのものが情報の資料(アーキ図・グラフ)を取り込むときは、md の該当箇所に自分で「(ここに◯◯の図)」と一行足すか、`--keep-source` で原本を残すことを検討する。ここが anydoc に倒したことで受け入れた最大の劣化。

スキャン PDF(pdftotext 変換)は anydoc の掃除とは性質が違う。見出し・表・リンクといった構造の推定はそもそも行っていないので、それらの癖は出ない代わりに構造も無い(段組は素のテキストとして流れて出る)。各ページの本文は先頭の `<!-- page N -->` コメントで区切られ、N は元 PDF の 1 始まりのページ番号(文字層が無く除外したページは番号が飛ぶ)。本文は OCR 結果そのものなので誤字が混じる前提で扱う。

md 冒頭に「- 種別: スキャン PDF」または「- 除外したページ: ...」の bullet が付いていたら、その md は素のテキスト層変換ではない。種別行が付いた md は OCR 結果そのものなので、引用・数値・記号は原本の該当ページで裏を取ってから使う(誤字を前提に扱う)。除外したページの扱いは次節参照。

### 4. スキャン PDF・文字層の無いページを除外したときの確認

一部のページだけ文字層が無く除外したとき、ingest.sh は stderr に `>> skipped pages (no text layer): 1,8,180` を出し、md 冒頭にも同じページ番号を記録する。このケースでは `--keep-source` を付けなくても原本が残る(agent が確認する前に消えないようにするため。stderr の `>> kept source ...` で分かる)。呼び出した agent は、除外された各ページを画像として読み、なぜ文字層が無いのか(表紙・白紙・写真や図版だけのページ・本文があるのに OCR が落ちている、など)を判断してユーザーに報告する。PDF ページを画像として読む手段は agent ごとに違う — 直接ページを画像として読める機能があるならそれでよい。無い環境では `pdftoppm -png -r 150 -f <N> -l <N> <pdf> /tmp/page` で PNG に書き出してから読む。画像を読む機能自体が無い agent では、その旨と除外ページ番号をユーザーに報告して判断を委ねる。本文があるのに文字層が無かったページは、その内容が md から欠けていることを明示して報告する(表紙や白紙なら欠落を気にする必要はない、とだけ伝えれば足りる)。この判定はページ画像を見て判断する仕事なので script ではなく agent が行う。確認が終わって原本が不要なら、agent が判断して削除してよい。

### 5. (任意)取り込み後の導線

一次情報は置いて終わりにせず、そのプロジェクトの index/ハブや、議論した日のメモから md へリンクを張ると後で辿れる。どこに張るかはプロジェクトの構造次第。

## YouTube の取り込み

YouTube URL は [references/youtube.md](references/youtube.md) を読み、同梱スクリプトで字幕を Markdown 化する。字幕が無ければ次の Anarlog 経路に進む。

## 字幕なし動画・ローカル動画

字幕の無い YouTube・mp4/mov・会議録画には [references/anarlog.md](references/anarlog.md) を読む。GUI import と文字起こしの完了を確認し、transcript と必要な映像情報を保存する。
