# リサーチ結果レポート（research）

技術調査・比較検討・事実確認など「問いに答える調査」のレポート型。材料と構成は [reporting](../SKILL.md)、語彙・図解・描画は [learn](../../learn/SKILL.md) に従う。

## 並び順

読者が知りたい順（結論・意思決定に近い問いから）。調査を実行した順・ソースを読んだ順にしない。

## 構成

- header のリード: 調査の問いと答えの要約を 1〜2 文で書く
- panel = sub-question / テーマ単位
- finding は箇条書き = 主張文。確度が低いものは主張文の直後（`[n]` の前）に `（未確認）` `（1 source のみ）` のような表記を付ける。確かなものは無印でよい（全件に一律表記しない）
- 出典は本文で `[1]` のように番号で参照し、末尾のSources panelと対応させる。SourcesではMarkdownリンクやコード位置など、読者が辿れる形で書く

## 矛盾・不一致

ソース間で主張が食い違うときはMarkdown表で対立を並べる。優劣が未確定の主張に `ok / no / warn` の判定を付けない:

| | 説 A | 説 B |
| --- | --- | --- |
| 論点 | 主張 [n] | 主張 [n] |

採る説（または判断不能）を 1 bullet で添える。

## 比較調査

技術選定・ライブラリ比較など選択肢を比べるときはMarkdown表にする:

| 観点 | A | B |
| --- | --- | --- |

行 = 比較観点。違いのない観点は書かない。表の直後に全体の結論と決定要因を1〜2項目で添える。採用が決まっている場合だけ採用結果を示し、調査中の候補を採用済みとして書かない。

## 末尾に必ず置く

- **わからなかったこと**: 確認できなかった・情報が見つからなかった項目を箇条書き。隠さない
- **Sources**: `[n]` + タイトル + 出典 + 種類（公式 docs / 一次資料 / 記事 等）が分かる補足。出典は URL とは限らない — ローカルコードを読んだ調査なら `path/to/file.ts:123` や commit SHA、社内ドキュメント名など**読者が辿れる形**で書く。**読者が非エンジニアでも省略しない** — 出典は調査の信頼性の本体であり、「識別子を本文に書かない」ルールの例外（`[n]` 参照も同様）

この2つのpanel名（「わからなかったこと」「Sources」）は固定ラベルとして使う。内容ではなく種類を示す名前のため、見出しに結論を入れるルールの例外とする。
