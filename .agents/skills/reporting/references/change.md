# 変更レポート（非 UI）

設定変更・データ移行・コード構造の変更など、画面を持たない「変更」のレポート型。型に共通するルール（図の要否・表・事実のみ書く等）は `../SKILL.md` の「構成の型」に従う。

## 並び順

処理の流れ順に並べる。ファイル一覧順・作業した順・レビュー回順にしない。

- データ移行: 読み取り → 変換 → 書き込み → 検証
- 構造変更: 入口 → 呼び出し → 末端
- 設定変更: 変更箇所の依存順（上位の設定 → その利用側）

## 構成

- section = 領域（機能・サブシステム・設定グループ）単位
- 各 section の本文は箇条書きで書く。1 bullet = 1 変更、動詞で終える文にする
- 設定値・状態が変わったことを見せるときは箇条書きに加えて `.state-table`（反映前 / 反映後）を併用してよい。変わっていない項目は書かない（差分だけ見せる）
