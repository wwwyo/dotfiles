# learn の適応意図

ユーザーが所有する学習スキルの名前を `learn` に統一し、QingYunA/answer-me-with-html の原稿から図解・動画を描画するエンジンを使う。旧 learn の個別制作を毎回繰り返さず、原本の自動配置・部品・単一ファイル出力を保つ。

教材の形式未指定ではHTML図解シートを使い、動画はユーザーが明示的に依頼した場合だけ作る。通常の「教えて」「図で説明して」や `/learn`、always-onの返答だけで動画を生成しない。短い定義や単純な手順、ユーザーが指定した形式は尊重する。読者が知る隣接概念との比較を入口に置く。教材を渡して終わらず、別例への適用など本人の理解が見える回答を待ち、誤解に合わせて説明と確認を繰り返す。閲覧だけを理解済みと扱わない。

reportingの共有成果物にも、learnの語彙・文章規範、図解部品、HTML描画、表示確認を使う。描画の実装や見た目の規約を呼び出し側へ複製しない。共有だけの依頼には本人の理解確認を付けず、学習依頼と区別する。画像は原稿の段階で埋め込み、CLIの単体HTMLと原稿からの再描画を保つ。大きな画像も縦横比を保ってパネル幅に収め、生成後のHTMLの修正を不要にする。

音声生成の運用仕様はmedia-generationを正本とし、learnはそこを参照する。learn側にモデル・話者・認証・読み分けの手順や独自のnarration referenceを持たせない。CLIの実装とhelpは実際の引数・動作を説明する。音声長に基づく図と字幕の同期を保ち、日本語の読みを修正した場合は音声キャッシュにも反映する。教材を作るagentと音声生成モデルを区別し、環境側のモデル選択・ツール管理・ブラウザ運用の正本を重複させない。

MP4書き出しは利用環境にあるH.264エンコーダーを使い、libx264が無いmacOSでも標準のVideoToolboxで生成できるようにする。教材のためだけに追加ライブラリやffmpegの再ビルドを必須にしない。既存のlibx264環境の画質設定と、Fish音声・字幕・図の同期は保つ。
