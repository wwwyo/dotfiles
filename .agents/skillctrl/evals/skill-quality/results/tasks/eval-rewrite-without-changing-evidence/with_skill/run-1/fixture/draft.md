# バックアップの新しい局面

本章では、バックアップの本質を正面から深掘りしていく。重要なのは、検査が信頼を運ぶということです。バックアップが成功と報告されても、復元できるとは限らない。ここには、安心の外側に世界が広がっている。

先週、運用担当者が検証環境で復元を試した。対象は週次バックアップ3件で、うち1件は設定ファイルが含まれていなかったためサービスを起動できなかった。ログからは、保存対象の指定が変更されていた可能性がある。ただし、変更した主体は分かっていない。残る2件はサービスを起動できたが、すべての機能を検証したわけではない。バックアップの成功ログは保存処理の終了を示すが、復元後のサービスの状態は確認しない。だから、保存の成功と復元の成功は同じ問題なのである。

## だから境界が要る

復元検査がすべてを解決する。しかし、検査に含めなかった障害は検出できない。この検査の対象は、検証環境でサービスを起動するところまでだった。次に運用担当者が行うのは、保存対象の指定を調べ、設定ファイルを含めたバックアップで再び復元を試すことである。要するに、バックアップの本質は、検査が信頼を運ぶということである。
