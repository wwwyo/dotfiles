1. root（集約）の関係

緑が root（5つ）。枠が集約で、白い箱は root の中に持つもの（外からは root を通してしか触らない）。実線は「中に持つ」、点線は別の集約を ID で指す参照。科目・内訳は歳出の中にあるので root ではありません。事業のつながり（分割・統合）は持たない。

root責務（何を守る集約か）守ること
自治体どの自治体かを決める（コード・名前・都道府県）自治体コードが一意
歳出1つの資料（当初・補正・決算）の1つの会計の歳出を、歳出の行（科目＝款・項・目、内訳）の金額で持つ。予算書・決算書は出どころ末端の科目の和が総額。内訳は科目と足さない
人口ある基準日の自治体の人口・世帯数を持つ自治体×基準日で1つ
事業評価自治体の1年度分の事務事業評価を、評価シート（小事業ごとの A〜D・今後の方向・指標）で持つシートの数・A〜D の数が評価結果の資料の件数と合う
事業 ★案予算書の事業の行を1つずつ事業にして年度をまたいでつなぎ（つなぎは風土記の判断）、親の事業、毎年の予算・決算の行、予算案の資料での説明を持つ。最小単位は末端の事業1つの年度に事業の金額は1つ。額を足すのは末端だけ

2. 集約の中（type）

各集約の root だけを表示する。下線の型を押すと、その object がその場で開く（もう一度押すと閉じる）。型の形で並べたもの。緑の見出しが root、白い見出しは root の中に持つもの。「〜コード」「〜ID」は別の集約を指す参照。★は案。

PK1件を決める項目（複数あれば組み合わせ）FK別の集約・マスタを指す項目
文字数・金額年度・日付選択肢（決まった値）はい／いいえobject配列ID出典URL

3. DB の表（今、D1 にある 14 表）

主キー・参照の列と主な列だけを載せています。「判断」と書いた参照は風土記が紐付けたもの。

緑の表が root に当たる表（jurisdiction・population・project_evaluation_result。事業の表は案）。歳出の root には1行の表が無く、科目・内訳の表の jurisdiction_code・fiscal_year・document_kind・amendment_number・account_name の組で決まる。fiscal_origin は出典（予算書・決算書）。どの表も jurisdiction_code で自治体を指す（線は代表だけ）。他の領域の表は主キーだけ載せています。
